# gafos Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a Rust CLI that reads an OpenAPI spec and rewrites the `spec.rules` of an existing Gateway API HTTPRoute so the gateway only routes requests the spec describes.

**Architecture:** Five focused modules — `config`, `openapi`, `translate`, `route`, `cli`. Pure data flows config → parse spec → translate to matches → splice the `rules:` region into the manifest as text (preserving everything else) → write or diff. The manifest is edited by locating and replacing a single byte region, never by whole-file reserialization.

**Tech Stack:** Rust (edition 2024), `argh` (CLI), `oas3` (OpenAPI 3.0/3.1), `saphyr` (span-aware YAML parse + emit), `similar` (diffs), `tempfile` (atomic writes), `anyhow`/`thiserror` (errors), `serde`/`serde_yaml` for config files.

**Spec:** `docs/superpowers/specs/2026-09-26-gafos-design.md`

## Global Constraints

- Rust edition 2024; crate name `gafos`.
- Scope is a single HTTPRoute's `spec.rules`. Never emit or edit anything else.
- Everything outside `rules:` is preserved byte-for-byte (comments, ordering, whitespace, trailing newline).
- Config precedence, lowest to highest: built-in defaults < `gafos.yaml` < `gafos.local.yaml` < CLI flags.
- `backendRefs` precedence: existing managed rules → config `backend` → empty.
- Default `path_match` is `regex`. Match dimensions (methods, query, headers) are independent, default off. Paths are always matched.
- Writes are atomic (temp file + rename). Never leave a half-edited manifest.
- `--check` exit codes: `0` in sync, `1` stale, `2` error.

## Review Focus

- **Regex-special characters in literal path segments** (e.g. `/v1.0/items`): the `.` must be escaped so the match is literal — pinned in Task 3.
- **Multiple templated params in one path** (`/a/{x}/b/{y}`): every param becomes `[^/]+`, statics stay literal — pinned in Task 3.
- **Comments adjacent to `rules:`** in the target manifest: must survive the splice unchanged — pinned in Task 5.
- **Trailing-newline preservation** (file with vs without a final newline): splice must not add or drop it — pinned in Task 5.
- **A file whose documents include one HTTPRoute plus other kinds** (e.g. a Service): target the HTTPRoute, leave the rest; error only on zero or multiple HTTPRoutes — pinned in Task 5.

**Interfaces:**

  - `struct PathRule { kind: PathMatchKind, value: String }`
  - `struct ParamPresence { name: String }` — rendered value is the regex `.+`
  - `struct Match { path: PathRule, method: Option<String>, query: Vec<ParamPresence>, headers: Vec<ParamPresence> }`

### Task 5: Locate and splice the rules region

**Files:**
- Modify: `src/route.rs`
- Test: inline `#[cfg(test)]`

**Interfaces:**
- Consumes: `render_rules_entry` (Task 4).
- Produces:
  - `struct RulesLocation { replace: Option<Range<usize>>, insert_at: usize, child_indent: usize, existing_backend_refs: Option<String> }` — `replace` is the byte range of the existing `rules:` entry (key through end of its block) when present; otherwise `insert_at` is where to insert a new entry at the end of the `spec:` mapping. `existing_backend_refs` is the raw YAML of the first rule's `backendRefs` value if any.
  - `fn locate_rules(manifest: &str) -> Result<RulesLocation>` — parse with `saphyr` using source spans; require exactly one document whose `kind` is `HTTPRoute` (other-kind documents in the file are ignored); error on zero or multiple HTTPRoutes; find `spec`, its child indent, and the `rules` entry span. Warn on differing `backendRefs` across rules and keep the first.
  - `fn splice(manifest: &str, location: &RulesLocation, entry: &str) -> String` — replace the `replace` range or insert at `insert_at`; preserve all other bytes including the trailing newline.
